Тест-план Объект тестирования: Medusa e-commerce, backend (Admin API + Store API), тестовое окружение (docker-compose: PostgreSQL). 

Цели тестирования: Проверить корректность создания товаров через Admin API. 
Проверить доступ администратора к API. 
Проверить создание корзины покупателем через Store API. 
Виды тестирования: функциональное (API, автоматизировано) + ручное регрессионное (UI-сценарии, не автоматизированы). 
Тестовое окружение: Backend: Medusa v2, локально через Docker (Postgres 15). 
Тестовые данные генерируются автоматически (уникальное имя товара через timestamp), не пересекаются между прогонами.
Из области тестирования исключено: нагрузочное тестирование, тестирование email-уведомлений, интеграция с внешними платёжными провайдерами, 
UI-слой (не автоматизирован — фронтенд нестабилен в локальном окружении, покрывается точечно вручную). 
Критерии входа: окружение поднято (npx medusa develop отвечает на BASE_API_URL), тестовый админ создан. 
Критерии выхода: все API-тесты зелёные; для регресса — не более 1 known issue без блокирующей критичности.
Риски: Нестабильность окружения (Docker/сеть) даёт false negative — снижается за счёт создания тестовых данных через API. 
Отсутствие автоматизации UI означает, что визуальные и вёрсточные дефекты можно поймать только вручную — компенсируется чек-листом ручной регрессии.
