Тест-кейсы TC-01 — Успешная аутентификация администратора Автоматизировано: да (API) 
Шаги: Отправить запрос аутентификации с валидными ADMIN_EMAIL / ADMIN_PASSWORD. 
Ожидаемый результат: получен валидный токен/сессия, последующие запросы к Admin API от имени этого пользователя проходят авторизацию. 

TC-02 — Аутентификация с неверным паролем Автоматизировано: да (API) Шаги: Отправить запрос аутентификации с валидным email и неверным паролем. 
Ожидаемый результат: запрос отклонён с ошибкой авторизации, токен не выдан.

TC-03 — Создание товара с обязательными полями Автоматизировано: да (API) Предусловие: авторизован как администратор. 
Шаги: Отправить запрос на создание товара: название, описание, статус «published», вариант (например, «Size: US 10») с ценой. 
Ожидаемый результат: товар создан, в ответе присутствует id, данные соответствуют переданным.

TC-04 — Попытка создать товар без названия Автоматизировано: да (API)
Шаги: Отправить запрос на создание товара без поля title. 
Ожидаемый результат: запрос отклонён с ошибкой валидации, товар не создан. 

TC-05 — Созданный товар отображается в списке через Admin API Автоматизировано: да (API) 
Предусловие: товар из TC-03 создан. Шаги: Запросить список товаров, найти по названию.
Ожидаемый результат: товар присутствует в списке со статусом «published» и корректной ценой. 

TC-06 — Товар отображается на витрине (storefront) Автоматизировано: нет — требует ручной проверки (UI не покрыт автотестами) 
Предусловие: товар опубликован (status = published). Шаги: Открыть витрину магазина в браузере. Найти созданный товар.
Ожидаемый результат: товар виден покупателю, цена и название совпадают с указанными при создании.
Примечание: выполняется вручную при регрессионном тестировании релиза. 

TC-07 — Создание пустой корзины (API) Автоматизировано: да (API) 
Шаги: Получить publishable key и sales channel id. Отправить запрос на создание корзины с валидным region_id.
Ожидаемый результат: ответ 200, в теле присутствует cart.id, валюта соответствует региону. 

TC-08 — Товар с ценой = 0 Автоматизировано: да (API) 
Шаги: Создать товар, указать цену варианта 0. 
Ожидаемый результат: (зависит от бизнес-правил — зафиксировать фактическое поведение: принято / отклонено с ошибкой валидации). 

TC-09 — Форма входа корректно отображается и валидирует поля на UI Автоматизировано: нет — требует ручной проверки 
Шаги: Открыть страницу входа в админ-панель. Проверить отображение полей, состояние кнопки при пустых полях, сообщения об ошибках. 
Ожидаемый результат: форма валидирует поля на клиенте до отправки запроса, сообщения об ошибках понятны пользователю.

Товар со статусом «draft» не отображается на витрине
